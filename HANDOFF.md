## What's Working (Verified)

### Backend (Go) ✓
- **Database**: PostgreSQL with full schema (migration `001_initial_schema.sql`)
- **Migrator**: Embedded idempotent migrator (`applied_migrations` table) applies `backend/internal/db/migrations/v2/*.sql` on startup. `002_dm_messages.sql` adds `dm_channel_id` to `messages` (nullable `channel_id`) for DM messages.
- **Auth**: JWT (access 15m + refresh 7d tokens), bcrypt, Google OAuth 2.0
  - `POST /api/v1/auth/register` - Register (returns `user` with **lowercase** JSON keys; `password_hash` is omitted)
  - `POST /api/v1/auth/login` - Login (requires `email_verified=true`)
  - `POST /api/v1/auth/refresh` - Refresh access token
  - `GET /api/v1/auth/me` - Get current user
- **Servers**: `GET/POST /api/v1/servers` - List/Create servers
- **Channels**: `GET/POST /api/v1/servers/:id/channels` - List/Create channels; `GET/PATCH/DELETE /api/v1/channels/:id`
- **Messages** (guild + DM): `GET/POST /api/v1/channels/:id/messages`, `GET/PATCH/DELETE /api/v1/channels/:id/messages/:message_id`; DM equivalents under `/api/v1/dms/:id/messages`
- **Reactions**: `POST/DELETE /api/v1/channels/:id/messages/:message_id/reactions[/:emoji]`
- **Members**: `GET/POST /api/v1/servers/:id/members`, `DELETE /api/v1/servers/:id/members/:user_id`, `PATCH /api/v1/servers/:id/members/@me`
- **DMs**: `GET/POST /api/v1/dms`, `GET /api/v1/dms/:id`, DM messages
- **WebSocket Hub**: Running on `/api/v1/ws`
  - Client→server opcodes: `IDENTIFY(0)`, `HEARTBEAT(1)`, `MESSAGE_CREATE(2)`, `TYPING_START(3)`, `MESSAGE_ACK(4)`, `VOICE_STATE_UPDATE(10)`, `CHANNEL_SELECT(20)`, `DM_SELECT(21)`
  - Server→client: `MESSAGE_EVENT(1)` (new message, with `message`+`author`+`reactions`), `TYPING_EVENT(4)`, `HEARTBEAT_ACK(6)`, `ERROR(5)`
  - Clients must send `CHANNEL_SELECT`/`DM_SELECT` after connect so broadcasts route to the right subscribers.
- **Health**: `GET /health` → `{"status":"ok"}`
- **Voice / Calls / Live** (`/voice/token`, `/calls/*`, `/live/*`): **implemented**. A `calls.Service` (`internal/calls/service.go`) mints LiveKit tokens, tracks call/stream state in memory, and signals ringing over the WS hub (`CALL_INCOMING` / `CALL_ACTION` / `STREAM_START`). Each call is recorded in `call_history`. Endpoints return **501 only when LiveKit credentials are absent** (`LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` / `LIVEKIT_WS_URL` must be set).

## Key Technical Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| SQL Library | pgx (raw) | No ORM overhead, full control |
| WebSocket | gorilla/websocket | Mature, well-tested |
| State | Zustand | Simple, performant, no boilerplate |
| Voice/Video | LiveKit Cloud | Managed SFU, React SDK, TURN included |
| File Storage | Local → S3/R2 later | Simple dev, scalable prod |
| Deployment | Docker Compose → K8s later | Simple start, container-native |
